┌─ 2. CRITICAL ARCHITECTURAL PROBLEMS ──────────────────────────────────────────┐
│                                                                                 │
│  Problem #1: DUAL CODE PATHS                                                   │
│  ─────────────────────────────────────────────────────────────────────────     │
│  Backend has TWO implementations:                                               │
│    • Modern API:      /health/nursing/api.py                                   │
│    • Legacy Code:     /health/nursing/modular_views/tasks/*.py                │
│                       /health/nursing/modular_views/calls/*.py                │
│                                                                                 │
│  Frontend uses BOTH (inconsistently):                                           │
│    • NewTaskModal  → Uses /api/tasks (modern API)                             │
│    • EditTaskModal → Uses /nursing/edit_task (legacy)                         │
│    • CallsList     → Uses /nursing/answered_call (legacy)                     │
│                                                                                 │
│  Impact: Legacy code has business logic that API bypasses!                    │
│                                                                                 │
│  ─────────────────────────────────────────────────────────────────────────     │
│                                                                                 │
│  Problem #2: TASK REPEAT BROKEN                                                │
│  ─────────────────────────────────────────────────────────────────────────     │
│  Legacy code (task_new.py) has full repeat logic:                              │
│    • Accepts: repeat_lapse, repeat_lapse_unit, repeat_until                   │
│    • Creates multiple tasks with same repeat_id                                │
│    • Sets correct states (soon/later/passed)                                   │
│                                                                                 │
│  Modern API has NOTHING:                                                       │
│    • TaskInputSchema only has: bed_id, task, programed_time, repeat           │
│    • Creates single task only                                                  │
│    • Ignores repeat parameters                                                 │
│                                                                                 │
│  Frontend collects repeat data but doesn't send it:                            │
│    • NewTaskModal collects: repeatLapse, repeatLapseUnit, repeatUntilDate     │
│    • But payload only sends: repeat (boolean)                                  │
│    • No repeat_lapse, repeat_lapse_unit, repeat_until in payload              │
│                                                                                 │
│  RESULT: Repeat tasks are NEVER CREATED!                                       │
│                                                                                 │
│  ─────────────────────────────────────────────────────────────────────────     │
│                                                                                 │
│  Problem #3: MISSING TASK MODEL FIELDS                                          │
│  ─────────────────────────────────────────────────────────────────────────     │
│  Model has:                                                                     │
│    ✓ repeat (boolean)                                                          │
│    ✓ repeat_id (string - for grouping)                                        │
│                                                                                 │
│  Model MISSING:                                                                │
│    ✗ repeat_lapse (int) - "2"                                                 │
│    ✗ repeat_lapse_unit (str) - "hours"                                        │
│    ✗ repeat_until (datetime) - end date                                       │
│                                                                                 │
│  These are needed for repeat logic to work!                                     │
│                                                                                 │
│  ─────────────────────────────────────────────────────────────────────────     │
│                                                                                 │
│  Problem #4: BED STATE NOT MANAGED BY API                                      │
│  ─────────────────────────────────────────────────────────────────────────     │
│  Task operations should change bed state:                                      │
│    • New task → bed_state = "task" or "call-task"                             │
│    • Task passed time → bed_state = "task" or "call-task"                     │
│    • Task deleted/done → bed_state = "occupied" or "call"                     │
│                                                                                 │
│  Legacy code handles this (task_new.py, task_edit.py, task_delete.py)        │
│  Modern API IGNORES IT completely!                                             │
│                                                                                 │
│  RESULT: Bed colors/states on frontend don't update correctly!                 │
│                                                                                 │
│  ─────────────────────────────────────────────────────────────────────────     │
│                                                                                 │
│  Problem #5: NO CALL CREATION ENDPOINT                                          │
│  ─────────────────────────────────────────────────────────────────────────     │
│  Calls are only created via MQTT messages!                                      │
│  API has:                                                                       │
│    ✓ answer_call - POST /api/calls/{id}/answer                                │
│    ✓ close_call  - POST /api/calls/{id}/close                                 │
│    ✗ create_call - MISSING!                                                   │
│                                                                                 │
│  Frontend uses legacy endpoint for answers:                                     │
│    • POST /nursing/answered_call (not in Django Ninja API)                     │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘

┌─ 3. STATE MANAGEMENT ──────────────────────────────────────────────────────────┐
│                                                                                 │
│  Frontend State Structure (appState):                                           │
│  ┌──────────────────────────────────────────────────────────────────────────┐  │
│  │ {                                                                        │  │
│  │   beds: [{ id, id_bed, bed_state, active, ... }],                      │  │
│  │   tasks: [{ id, bed_id, task, state, repeat, repeat_id, ... }],        │  │
│  │   calls: [{ id, bed_id, state, response, ... }],                       │  │
│  │   patients: [{ id, name, diagnosis, ... }]                             │  │
│  │ }                                                                        │  │
│  └──────────────────────────────────────────────────────────────────────────┘  │
│                                                                                 │
│  Updated via:                                                                   │
│    1. Initial load: fetchLoad() → /api/app/load                               │
│    2. WebSocket: appManager() → /ws/appData/                                  │
│    3. Manual refresh: After task/call operations                               │
│                                                                                 │
│  WebSocket Flow:                                                                │
│    Backend creates data → app_ws_update() → layer.group_send('appboard')     │
│    Frontend consumer → handles message → setState()                            │
│                                                                                 │
│  Issue: Some operations use old endpoints that may not trigger WebSocket      │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
